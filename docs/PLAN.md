# APK-PATCH Plan: Apktool Parity in Pure Rust

**Goal:** A pure-Rust tool to unpack, edit, and repack Android APKs, built on the [Androguard](https://github.com/androguard) crate suite — functionally equivalent to [Apktool 3.x](https://github.com/iBotPeaches/Apktool), but using a **native DEX text format** instead of smali/baksmali, and with **automatic APK signing** built in.

**Reference:** [Apktool](https://github.com/iBotPeaches/Apktool) · [Apktool CLI docs](https://apktool.org/docs/cli-parameters)

**Current state:** Phase 0–3 complete, including Phase 3b pure-Rust ARSC builder (default rebuild path). aapt2 remains optional (`--use-aapt2`). Signing, frameworks, dex-txt, and resource decode/encode are in place.

**Workspace crates:** `apk-patch-cli`, `apk-patch-core`, `apk-patch-meta`, `apk-patch-project`, `apk-patch-dex`, `apk-patch-framework`, `apk-patch-resources`, `apk-patch-sign`

**Test status:** 35+ unit/integration tests passing.

---

## Core Principles

1. **Pure Rust** — no Java runtime, no smali/baksmali, no bundled aapt1.
2. **Extend existing crates** — grow `dex-parser`, `dex-bytecode`, `axml-parser`, and `apkparser` rather than reinventing them.
3. **Functional parity with Apktool** — same CLI workflow, project layout, metadata, and rebuild semantics; code is stored as **DEX text**, not smali.
4. **Sign on build** — rebuilt APKs are signed automatically (v1 + v2/v3), not left unsigned like Apktool.

## Code Representation: DEX Text (not smali)

Instead of smali, extend **`dex-parser`** with a human-readable text format called **dex-txt**.

### What it is

A line-oriented text representation of DEX structure, emitted from and parsed back into `dex-parser` types. Instruction lines reuse **`dex-bytecode`** mnemonics (already used by `dex-bytecode-dis`).

Example (illustrative):

```
# classes.dex — generated by apk-patch
.class Lcom/example/MainActivity;
.super Landroid/app/Activity;

.field private count:I

.method public onCreate(Landroid/os/Bundle;)V
    .registers 4
    .line 12
    const/4 v0, 0
    invoke-super {p0, p1}, Landroid/app/Activity;->onCreate(Landroid/os/Bundle;)V
    return-void
.end method
```

This is **not** smali syntax. It is a simpler, Androguard-native format tied directly to `DexFile`, `ClassDef`, `MethodInfo`, and `CodeItem`.

See [DEX-TXT.md](./DEX-TXT.md) for the format specification.

**Phase 1 implementation note:** dex-txt emit/parse/assemble lives in `apk-patch-dex`. Assembly builds a **new DEX from scratch** via `dex-parser::DexBuilder` (mnemonic + operands are authoritative). Hex on emit lines is comment-only; payloads use `.hex` raw bytes. `dex-bytecode` provides full mnemonic encode; `replace_code_insns` remains available for low-level patches.

### On-disk layout

Apktool uses `smali/`, `smali_classes2/`. APK-PATCH uses parallel directories:

| DEX file | Directory |
|----------|-----------|
| `classes.dex` | `dex/` |
| `classes2.dex` | `dex_classes2/` |
| `path/to/foo.dex` | `dex_path@to@foo/` |

Same naming rules as Apktool, different prefix (`dex_` instead of `smali_`).

### Extensions to `dex-parser`

| Module | Purpose |
|--------|---------|
| `dex/txt/emit.rs` | `DexFile` → text files (one file per class) |
| `dex/txt/parse.rs` | text → in-memory DEX structures |
| `dex/write.rs` | structures → valid `.dex` bytes (checksum, signature, map_list) |
| `dex/txt/debug.rs` | optional `.line`, `.local`, `.param` (controlled by `--no-debug-info`) |

`dex-bytecode` remains the instruction layer: mnemonics, operand formatting, and encoding helpers (to be extended beyond today's branch/nop patch API).

### Decode/build flags (Apktool semantics, dex-txt output)

| Flag | Behavior |
|------|----------|
| default | disassemble root `classes([2-9]\|[1-9][0-9]+)?.dex` → `dex*` dirs |
| `-a` / `--all-src` | disassemble all root `.dex` files |
| `-s` / `--no-src` | copy raw `.dex` unchanged |
| `--no-debug-info` | omit debug annotations in dex-txt |

## Apktool Parity: What Matches, What Differs

| Area | Apktool | APK-PATCH |
|------|---------|-----------|
| CLI commands | `d`, `b`, `if`, `cf`, `lf`, `pr` | Same |
| Project metadata | `apktool.yml` | Same (3.x schema + 2.x import) |
| Resources | `res/` tree | Same |
| Manifest | text `AndroidManifest.xml` | Same |
| Assets, lib, unknown, original | same dirs | Same |
| Code format | smali | **dex-txt** (Apktool projects not interchangeable for code) |
| Build output | unsigned APK | **signed APK** (default) |
| aapt2 for resources | yes | optional (`--use-aapt2`); pure-Rust ARSC builder is default |

**dex-txt insn format:**

```

```

Labels are named; offsets are computed at assemble time. Hex is comment-only (except `.hex` for switch/array payloads). Pool indices are not stable across rebuilds.

## Automatic APK Signing

Unlike Apktool, signing is a **first-class build step**.

### Default behavior

```
build → zipalign → sign (v1 + v2 + v3) → dist/app.apk
```

### Implementation (`apk-patch-sign`)

| Scheme | Approach |
|--------|----------|
| **v1 (JAR)** | Sign `META-INF/MANIFEST.MF`, `.SF`, `.RSA` / `.EC` using `rsa` / `p256` crates |
| **v2/v3** | Build APK Signing Block (central directory offset, signer pairs, digests) |
| **zipalign** | 4-byte align uncompressed entries before signing |
| **Debug keystore** | Embed or generate `~/.android/debug.keystore` equivalent on first use |
| **Release** | `--ks path`, `--ks-key-alias`, `--ks-pass`, `--key-pass` |

### CLI flags (beyond Apktool)

| Flag | Purpose |
|------|---------|
| `--no-sign` | Output unsigned APK (Apktool-compatible behavior) |
| `--ks PATH` | Keystore path |
| `--ks-pass PASS` | Keystore password |
| `--ks-key-alias ALIAS` | Key alias |
| `--key-pass PASS` | Key password |
| `--v1-signing-enabled` | Toggle v1 scheme (on by default) |
| `--v2-signing-enabled` | Toggle v2 scheme (on by default) |
| `--v3-signing-enabled` | Toggle v3 scheme (on by default) |

### Library changes in `apkparser`

```rust
// apkparser/src/sign/mod.rs
pub fn sign_apk(apk_bytes: &[u8], options: SignOptions) -> Result<Vec<u8>>;
pub fn zipalign(apk_bytes: &[u8], alignment: u32) -> Result<Vec<u8>>;
```

## Risks

| Risk | Mitigation |
|------|------------|
| dex-txt format design | Start minimal (classes + methods + insns); iterate with roundtrip tests |
| DEX writer correctness | Mirror `dex-parser` parse tests in reverse; compare bytes where possible |
| Resource encode complexity | pure-Rust ARSC builder ✅; bag/style fidelity still evolving |
| Signing v2/v3 spec | Follow Android SDK spec; test against `apksigner verify` |
| Not smali-compatible | Document clearly; dex-txt is simpler and Rust-native by design |
| No Androguard workspace root | Use path deps from `apk-patch`; propose monorepo workspace later |
